# 技术设计：持续理解与生成式工作产物

> 实施更新（2026-09-11）：本轮已开始并完成一版本地实现。本文保留原设计目标；“尚未开发／下一轮”等为设计阶段记录。当前实现差异与平台边界见 [ADR-003](adr/003-cross-platform-first-version.md)，实际通过与未测项目见 [验证记录](../tests/results/validation.md)。
版本0.1｜2026-09-11｜状态：可供下一轮实施的建议设计，未安装、构建或实测。业务要求见[产品定义](product-definition.md)，数据细节见[契约](contracts.md)。

## 1. 建议运行结构

```text
线下麦克风 ──→ STT适配 ───────┐
线上系统音频＋麦克风 → STT适配 ├→ 标准段落／来源／身份
平台实时转写 ─────────────────┤
标注的文字／录音回放 ─────────┘
                                  ↓
                    可信本机会话服务：保存与调度
                                  ↓
                    理解工作流 → 会议对象与关系
                                  ↓
                    表达规划 → 生成 → 校验／渲染验证
                                  ↓
                    产物版本 → 桌面工作区／轻量入口
                                  ↑
              用户操作 → 可信命令入口 → 比较／试算工具
```

初始建议：TypeScript；Electron负责生命周期、采集授权和窗口；React负责可信外壳；会话服务运行于独立的可信本机进程；SQLite保存会议状态。利用Electron的utility process承载服务是候选方案，避免模型等待或数据库工作阻塞窗口主进程。[S01、S03](sources.md)

模型提供商通过适配接口替换。初期普通异步工作流即可，不强制LangGraph；保留理解、表达生成、校验的独立接口，后续改变编排库不改业务契约。版本在实际开发时选择并写精确lockfile，不在文档里捏造已安装版本。

可信桌面壳、窗口与语言配置按[前端规范](frontend-spec.md)和[语言规范](language-spec.md)实施。选定浅色轻导航结构是设计基线；UI本地化、输出locale与原话语言不能合并成一个设置。

默认个人本地事件；云端模型访问由可信会话服务发起。离线会议不等于离线运算；客户端不内置团队共享密钥。原型可由运行者向本机可信服务提供自己的开发凭证；分发给其他用户时另选各用户凭证或认证云网关方案。

## 2. 输入接通与身份

| 路线 | 实现责任 | 通过条件 |
|---|---|---|
| 线下 | 可信采集窗口取得指定麦克风；格式转换、STT、断流标记 | 多名真实测试者的发言实际进入统一段落；报告噪音与距离 |
| 线上本机 | 验证目标系统的系统音频与本机麦克风；标通道、处理回声／重复 | 耳机中的远端声音和本机发言均实际可达；不能用外放漏音冒充 |
| 平台转写 | 独立适配平台鉴权、事件、参与者与段落 | 在有权限的真实会议中收到远端内容；账号身份仍需校验 |
| 合成回放 | 输入固定标准段落 | 用于语义与状态验证，不证明音频链路 |

Electron具有桌面采集接口，但音频行为、系统版本与权限有差异；先验证实际音轨，不能只看返回了MediaStream就报成功。[S02](sources.md) Zoom RTMS是候选平台输入，媒体与身份字段以实际载荷为准；不强制安装Zoom App展示页面。[S04](sources.md)

当前OpenAI实时转写指南的推荐路线不返回说话人标签。专用文件转写可提供分组，但不能直接宣称具有相同实时性能。[S05、S06](sources.md) 先让内容链路正确运行；若增加分组模块，需验证跨片段稳定性和身份映射。`unknown`是合法产品状态。

同一事件首版一次只启用一种主输入拓扑。双通道应有`channelId`与来源角色；是否同一句重复不能仅靠文本相同判断。平台转写已用时，不同时叠加同一会议室麦克风造成重复。

## 3. 状态、调度与持久化

可信服务是唯一业务写入者。React状态、LLM上下文、生成HTML及SVG都不是权威数据库。

建议表：`meetings`、`sources`、`identity_mappings`、`segments`、`objects`、`relations`、`artifacts`、`artifact_revisions`、`scenarios`、`decisions`、`commands`、`jobs`。以类型化JSON保存内容，但由共享schema校验；来源与依赖可建立可查询索引，不必每次全库扫描。

- 每场会议理解批次并发1；表达生成初始并发1，持续输入独立入库。
- 稳定段落合并初值500ms，最迟等待1500ms启动批次；这些是待调参数。
- 进度包含已接收段落水位、已理解水位、产物依赖版本；理解落后初值5秒时显示积压。
- 无展示或无网络时不无限堆积内存。原型音频缓冲初值最多2秒；超限记录缺口，不暗中保存整场录音。
- jobs有幂等键、attempt、租约与取消状态。重启可恢复已保存段落的处理；不会自动恢复采音。
- 数据库事务短，不包含模型或网络调用。SQLite单写服务；不存在两个数据库副本“自然同步”。

## 4. 理解与生成的两段工作流

### A. 理解与表达规划

`loadContext → interpretDeltaAndPlan → validateSemanticDelta → commitUnderstanding`

输入包含本批段落／版本、相关话题与对象、修正链、已存在产物索引和用户当前请求。近期上下文加按对象／关键词查回的旧来源；不能因固定时间窗漏掉话题回归。初值token预算6000可调，但关键来源和对象不能静默截断。

一次主要模型调用可同时返回`SemanticDelta`与`ExpressionPlan`，服务分别校验。文本与结构化输出模式由供应商适配；schema成功不意味着语义正确。[S07](sources.md) 若表达规划失败，可先提交合法理解并单独重试规划。

模型可以提出新对象，服务分配稳定ID；以批内临时引用解决新对象相互引用。可信服务校验真实read set与输入版本，不采信模型自报的权限或最新版本。

理解提交后，服务用实际提交结果解析临时ID，并将表达计划绑定到这次提交后的对象／关系revision。读入的旧revision仅用于提交冲突校验，不能原样作为新产物的依赖版本，否则产物会立即过期。与此提交无关的依赖保持原版本；任务创建前再次检查它们仍有效。

### B. 产物准备与验证

`prepareGenerationContext → generatePayload → validatePayload → renderCheck → publishRevision`

- 普通文字或已完整生成的描述可以直接校验，不额外调用模型制造等待。
- SVG／HTML等需要代码生成时才单独调用生成器；只传当前产物需要的对象投影与来源，不传凭证或无关会议。
- 语法、来源、操作与大小校验通过后，在受控预览环境渲染；检查溢出、内容边界、渲染错误与交互绑定。
- 简单边界检测不能证明图形语义正确；语义断言与人工可读性核查分别报告。
- 一次定向自动修复后仍失败：保留最后可用产物，明确错误，允许用户重试；无旧产物时显示简短已验证重点与“图形未生成”。不声称降级文字等于图形成功。
- 用原计划依赖版本和generation提交。输入只发生无关变化不必作废；相关变化则废弃或基于新状态重生。
- 生成上下文包含目标outputLocale、languageRevision与visualProfileId。提交同时检查这些表达配置，避免语言切换后旧任务覆盖新语言；翻译不更新业务事实。

## 5. 模型职责与工具

理解模型提炼陈述、条件、风险、关系、选项、时间和未知；表达模型规划与生成，不负责选择文件路径、网络目标或授予权限。二者是模块角色，可使用同一个模型，不要求多Agent。

允许的业务工具：按ID读来源、查询会议相关对象、校验关系、计算明确算式、比较给定方案、创建独立试算提案。默认无任意浏览、发送消息、系统shell或执行生成代码的工具。

算法性结果由工具负责：

- 金额以币种最小单位或精确十进制定点处理，范围与单位校验后计算。
- 公式可来自明确输入或经过用户确认的关系；先转白名单表达式树，再由计算器执行。禁止`eval`和无依据公式。
- 日期以会议时区解析，保留原相对表达和参照日期。日期不等于工期；工作日、自然日及节假日信息不足时仅给条件性结果。
- 方案的定性差异保留原条件；没有权重和依据不做综合分数。

## 6. 命令、并发与修正

所有模型增量、用户纠错、试算保存和决定记录经`executeCommand`。可信命令绑定请求哈希；相同ID不同内容拒绝；重试相同命令返回原结果。

提交检查会议权限与生命周期、输入revision、对象read set、产物generation；冲突返回差异。模型重理解最多一次，持续冲突则保留待处理，不无限追逐。

转写revision替换：查询引用旧版的对象、关系、产物和试算。无后续独立编辑时允许受校验修订；已有独立编辑、确认或别的新来源时显示冲突／过期，不全局倒放。受影响的确认快照保持历史版本，追加修订建议。

用户拖动／编辑先产生本地试算草稿，不能改会议事实。提交基于明确baseRevision；来源改变时提示重算。个人采纳产生个人范围记录；记录会议决定必须另填范围与来源，不自动升级。

## 7. 桌面通信与展示

可信shell通过窄preload桥调用会话命令与订阅；main负责验证发送者并路由到服务。生成内容没有这个桥。

`meeting.snapshot`、`understanding.updated`、`artifact.status`、`artifact.available`、`capture.status`、`processing.status`为主事件。快照带递增revision；订阅先注册缓冲，再读快照及水位，避免漏更新。视图恢复重取快照。

轻量入口与工作页复用同一会话状态；窗口不是会话本身。默认关闭工作页隐藏到托盘，后台持续；明确退出时提示正在进行的采集，并完成停止流程。生成预览使用独立WebContents等受控环境，不在主进程解析／执行生成脚本。

桌面可见入口与系统托盘是互补入口，不用一个任务栏图标替代已确认的悬停／右键体验。左键聚焦现有工作页，默认不强制置顶。语言字典、原生菜单、辅助标签和错误提示统一使用locale；快捷键不干扰输入法组合。

## 8. 停止、保存与数据边界

用户开始前显示音源、传输到的STT／模型提供商、内容保存范围。默认原始音频不落盘；原型会话文本和产物本地保存至用户删除，结束页可删除。本地保存不等于供应商零留存，其策略需按选用账号另核验。

停止先撤销capture epoch、停止设备与上游输入，最多收尾2秒已有缓冲（参数可调），截定水位。已收内容的理解与产物任务可继续，显示“整理已接收内容”，不能显示仍在采音。重启／恢复不自动重开麦克风。

存储目录使用操作系统应用数据目录，不能放在源码仓库或同步盘代码树中。日志默认ID、状态、耗时、token和错误码；不记录凭证、原始音频和完整发言。导出含来源、假设、确认范围和版本；用户明确触发后写文件。

## 9. 可观测性与边界

追踪链：`meetingId → sourceEpoch/segmentId/revision → batchId → modelCallId → commandId → objectRev → artifactId/generation/revision`。记录token、模型、等待、生成、渲染和提交耗时，区分字幕在线与理解积压。

初始工程目标：稳定段落到理解提交p95≤5秒；完整新产物单独记录，不与该指标混淆；展开已缓存速览≤300ms；简单本地试算≤100ms。都是验收目标，未实测；未达到时报告原因与实值，不伪造即时结果。

账户模型、费率和额度需实查；未取得可信费率前用token／调用／时长限制，不能称精确货币预算。云端调用失败时原有结果可查看，新的理解明确暂停。
