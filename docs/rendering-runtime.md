# 生成表达的承接与运行环境

> 实施更新（2026-09-11）：本轮已开始并完成一版本地实现。本文保留原设计目标；“尚未开发／下一轮”等为设计阶段记录。当前实现差异与平台边界见 [ADR-003](adr/003-cross-platform-first-version.md)，实际通过与未测项目见 [验证记录](../tests/results/validation.md)。
状态：实现方案建议，需在选定桌面环境实测。产品自由度见[表达语言](expression-language.md)，接口见[契约](contracts.md)。本文约束执行能力，不把自由表达缩成固定业务模板。

## 1. 三层职责

1. **Agent**决定用户问题、内容结构、载体、布局意图与必要交互。
2. **可信表达宿主**维护产物ID、来源、版本、渲染尺寸、错误、可信操作入口与状态投影。
3. **渲染适配器**承接具体文字、图语言、SVG、图表描述与HTML。每种适配器统一提供`validate, render, measure, update, dispose`能力。

内部元素→业务对象→来源的绑定必须保存。只保存SVG截图会失去来源与可维护性；只存模型上下文不能恢复已保存产物。

所有载体接收`visualProfileId=editorial-light-v1`、目标locale与可用尺寸；参考[前端规范](frontend-spec.md)和[设计tokens](design/tokens.json)。磨砂只由宿主在外围层提供，生成内容不能自行创建整页玻璃、极小字或全局样式。缺少效果时退回实色，不影响业务操作。

## 2. 各种载体

| 载体 | 内容格式建议 | 校验和更新 |
|---|---|---|
| text／table | 结构化文档块；可导出Markdown | 类型、长度、来源、层次和单元格状态；按块稳定ID更新 |
| diagram | Mermaid或通用节点／边描述 | 允许的图语法、关系语义、节点绑定、边界；稳定对象坐标优先 |
| svg | Agent生成SVG＋绑定清单 | XML解析和元素／属性允许名单、尺寸、文字、引用；候选通过后整版替换或受控元素更新 |
| chart | Vega-Lite等图表规范＋已知数据 | 轴与单位、数据来源、表达式／transform限制、内联数据与范围；参数和选择交互 |
| html | HTML＋受约束CSS＋可选受控JS＋绑定清单 | 独立沙箱预览、无外部资源、界面边界、事件桥、资源限额 |

Mermaid可将图描述渲染成SVG；Vega-Lite通过声明参数和选择支持交互。[S08、S09](sources.md) 这些能力仍需我们编写绑定和更新逻辑，不能把库支持当作本产品已实现。

## 3. 基础内容规范

文本按数据渲染，不将会议原话当HTML。图语言禁用未受控的HTML标签与回调；需要来源点击时由宿主按元素映射提供受控交互。不要为打开一个引用就整体放宽图语言安全设置。

SVG不默认是静态无风险内容。拒绝script、foreignObject、事件处理属性、外部链接／图片／字体和外部CSS引用，检查嵌套引用、路径数量及尺寸；允许名单随实现具体化。作为图片使用时脚本受到限制，但也无法直接提供节点级交互。[S10](sources.md) 若需交互，净化后在隔离内容层渲染并只传声明的操作请求。

Chart只接受明确来源的内联数据，不允许任意远端URL加载或未检查表达式。复杂数据变换应尽量由可信工具计算；可视化层结果不能自行写入会议决定。

## 4. HTML的实际边界

工程建议采用独立、sandboxed的WebContents表达宿主，不与可信React壳共用Node或preload业务接口；必要时在其中再用无同源权限的iframe承载生成内容。不能仅凭一个iframe标签宣称完成隔离。

候选HTML在此层可安排布局、渲染SVG、运行有限本地交互。禁止网络请求、文件／系统访问、设备权限、任意窗口导航、下载、弹窗与跨会议读取。资源由宿主预打包，不在运行时由模型指定CDN。CSP、session请求拦截、权限处理、导航限制和Electron配置共同落实边界。[S01、S11](sources.md)

若使用iframe，建议`sandbox="allow-scripts"`且不授予`allow-same-origin`，但具体配置须在目标运行环境验证。生成JS不能获得Electron APIs；可信主进程不执行它。表达宿主需有独立看门狗和终止能力，避免死循环冻结整个应用；隐藏iframe本身不构成资源隔离。

初始限制建议：单产物载荷256KiB、DOM节点1000、渲染预览期限3秒；超限拒绝或请求简化。限制是工程初值，不是性能保证；不同载体可调整，不能通过无限增大掩盖冗长产物。

## 5. 产物交互桥

生成内容只能发`ArtifactActionRequest`：

```ts
type ArtifactActionRequest = {
  artifactId: string; revision: number; actionId: string;
  requestId: string; payload: unknown;
};
```

接收端检查消息来源窗口／frame、当前事件、artifact revision、动作允许名单、payload schema与频率。opaque origin的`null`不作为信任依据；会话随机绑定可以防混接，但不能把生成页面变为可信方。

- 查看来源／展开：宿主解析绑定并展示当前可见内容，生成页面不能自造路径或跨会查询。
- 请求比较／试算：产物可提交意图与草稿；可信宿主显示实际对象、条件和作用范围，由用户明确触发相应模型／工具工作。高频拖动的本地预览限在已有授权试算内，实际保存另走可信命令。
- 纠正原话、采纳、记录会议决定、导出或停止采集：只在可信外壳完成。生成脚本自动发出的消息不能构成人的授权。

操作按钮和结果不能被生成页面伪装成已保存／已确认。宿主在生成区域外提供真实状态；所有成功与错误由服务回传。

## 6. 更新与阅读稳定

生成内容不直接修改DOM中的旧业务事实。服务提供只读投影与revision；产物在离屏／独立预览中准备完成，依赖版本有效后才提供给可见层。

- 同一个产物修改日期或节点，保留artifactId与对象绑定；候选revision不可原地污染旧版本。
- 阅读中记录选中对象、滚动锚点、展开状态和用户输入；更新后恢复。重新布局不可保持时提示“有更新”，由用户切换。
- HTML本地草稿在替换前映射到声明的inputId；schema或绑定不兼容时保留草稿并提示，不静默提交或丢弃。
- 当前话题没有意义变化，不重新生成。同一批次重复就绪事件不反复通知。
- 引用来源修正后，新依赖未验证的结果标为过期；不能仅改标题后让下方数值继续看起来有效。
- 切换输出语言可能需要重排，必须保持业务对象与来源；迟到的旧locale产物不得替换新目标。翻译结果未经校验时保留旧版并标记语言更新状态，不清空工作区。

## 7. 预览与质量检查

必须依次通过：解析／schema → 来源与对象 → 允许的操作 → 渲染／资源 → 可读性。

初始检查包括：屏幕与浮层两种尺寸、文字边界、容器overflow、重复ID、节点重叠、轴单位、颜色对比、可达操作与运行错误。自动测量只能发现部分问题，三类语义样例还需人工核查表达是否解决问题。

失败不发布半成品，保留旧产物与新理解状态；如果此前没有产物，给简短可信文字作为临时降级，并明确图形失败。最多一次自动修复；手动重试有新jobId与依赖水位。

## 8. 为什么不直接生成整页应用

固定业务模板会限制用户确认的生成能力；任意完整应用又把会议状态、权限和表现绑在一起。采用通用载体＋可组合产物，使Agent拥有结构自由，同时让宿主控制来源、状态和真实业务操作。

运行环境必须用实际生成内容、异常HTML、过大SVG、无效图语言和脚本循环测试。通过静态示意图不能证明这些能力完成；验收见[标准](acceptance-criteria.md)。
