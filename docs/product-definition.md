# 产品定义：会议事件中的生成式表达

> 文件职责：产品／工程设计要求，不是完成清单。当前进度与最新修订见[状态页](status.md)；已交付首版取舍见[ADR-003](adr/003-cross-platform-first-version.md)，实际结果见[验证记录](../tests/results/README.md)。具体实现以代码核对，未实现的要求仍是目标。
基线：`meeting-event-generative-v3`｜2026-09-11。产品认知来源为本轮用户连续确认；本文是产品目标和后续迭代的业务依据，不表示功能已完成。技术选型见[决策记录](decisions.md)。

当前 demo 优先级：让评委看见Agent主动形成、展开和修订思路图／关系表达；在有结构时及时可视化，并呈现实际处理中的变化。具体规则与替代关系见[Demo实时表达](demo-live-visuals.md)。这不放宽事实和来源要求，也不将所有讨论强制画成同一种图。

## 1. 核心价值与形态

2026-09-12范围增补：用户要求设计可选首版协作模式，支持投票、分工、冲突、决定确认；Agent准备带预设schema／样式的组件，发起者发放，参与者交互，首阶段本地模拟。完整规则见[协作设计](collaboration-v1-design.md)。核心本地模拟已随 PR #3 合入主线；完整设计仍有缺口，见[实际运行时](collaboration-v1-runtime.md)。普通个人按需查看和通用生成式表达仍成立。

一个支持线上与线下会议的桌面助手，以每场会议为独立事件。Agent持续理解正常讨论，自主规划、生成和修订简洁的文字、可视化与交互产物；用户按需查看、纠正、提问和推演，结束后保留有来源的结果。

用户不必为了产品把自然讨论改成逐句指令。工作区不是不断增长的聊天气泡，Agent也不复述一份比会议更长的解释。目标是让用户更快看懂关键关系，并继续推进讨论。

## 2. 用户和三层界面

| 层次 | 用户看到什么 | 行为 |
|---|---|---|
| 会议列表 | 每场事件的名称、时间、进行／结束状态；用户建立的主题文件夹 | 新建、打开、回看；不把不同会议**自动**混成一个上下文。用户显式建立文件夹属于已确认范围，见第 7 节 |
| 事件工作区 | 当前焦点、Agent生成的工作产物、重要变化与来源入口 | 阅读、纠错、比较、调条件、查看决定和未决项 |
| 轻量入口 | 真实运行状态，悬停直接呈现当前会议 Agent 画板并实时更新 | 悬停查看、移开收起、点击打开工作页；隐藏时仍理解 |

事件工作区的工具栏、采集状态、导航由应用提供；内容主体由Agent按会议需求生成。可以提供多种查看方式，但不预设每场会议都要有相同栏目或所有图表。

页面外观采用用户本轮认可的 8 张概念图所呈现的清晰、浅色现代协作办公方向，见[风格与页面规范](design/style.md)和[前端规范](frontend-spec.md)。已按此方向实现 `collaborative-light-v2`，并按用户要求参考飞书云文档／会议等布局细化；[实际功能与目标边界](frontend-spec.md#11-当前实现与目标差距)单独维护。旧第二张图保留为历史；整体认可不等于每个补充状态已实现或逐项验收。语言默认跟随系统（中文系统用简体中文，其余英文），设置可覆盖；界面、会议输出、语音输入语言分开，见[语言规范](language-spec.md)。这些是已确认要求，不留给开发任意决定。

## 3. 输入场景

- **线下会议**：建议由一台设备选择麦克风开始记录；不要求所有人同时安装并录音。设备距离、噪音、重叠发言及身份质量需实测。
- **线上会议**：选择受支持的平台内容流，或已验证的本机系统音频＋麦克风路线。Zoom只是其中一种适配器，不是产品定义。
- **混合会议**：产品可建模多来源，但首版不承诺自动解决平台流与会议室麦克风的重复采集；检测到重叠输入风险时要求选主来源或明确通道。
- **回放／文字输入**：供开发测试使用，持续标记其真实来源，不当作实时采音已完成。

线下指人同处一室，不等于无需网络。建议原型调用云端模型；无网时不可声称继续完成模型理解。离线模型属于独立后续路线。

## 4. 用户闭环

| 步骤 | 系统职责 | 可观察结果 |
|---|---|---|
| 开始事件 | 使用已保存的音频设置；首次配置／失败才询问，语言自动解析，标题由内容生成 | 一次点击衔接创建与采集，真实就绪才显示收听；详见[会议入口规范](meeting-entry-spec.md) |
| 自然讨论 | 前文与新内容关联，保留原话、观点、条件和变化 | 无需逐句命令，未知项不被补造 |
| 按需查看 | 从已维护状态给出紧凑速览或完整产物 | 打开即接上前情，不在打开后才开始理解 |
| 深入工作 | 围绕选中内容提问、拆解、比较、调整条件 | 生成有用产物，试算不改原话 |
| 修正与确认 | 保留变更范围、版本、来源与操作者 | 个人采纳与会议决定分开 |
| 结束保存 | 截止输入、释放资源、保存表达和未决问题 | 可回看、可导出；恢复内容不自动恢复录音 |

会议层面闭环止于形成可追溯、可接着执行的结果。PR #3 的可选协作扩展允许发起者检查并发放组件、提出分工、收集本人回应；不能替别人接受任务或确认决定。自动向外部平台发消息、催办或跨系统执行不在当前核心；具体范围与尚未关闭的缺口见[PR 对照](pr3-doc-alignment.md)。

## 5. 展示状态与采集状态

展示：`collapsed → peek → workspace_open`。悬停进入peek，直接呈现当前会议 Agent 画板及实时修订；指针在入口和浮层的联合区域内保持展开，离开后收起，不抢正在开会的窗口焦点。拖动入口不打开画板。左键打开并持续显示工作页，关闭回collapsed。此前pinned意指持续显示，不要求额外图钉步骤或系统强制置顶。右键菜单状态独立；键盘提供等价入口。详细转移和尺寸见前端规范。

采集：`idle → starting → capturing → paused / input_error → capturing → draining → stopped`。后台理解与产物任务另有各自进度；不能用“录音中”掩盖模型积压。

- 收起或关闭工作窗口不停止会话服务，托盘入口应可恢复；退出整个应用必须明确处理仍在采集的事件。
- 工作页默认实时跟随会议，普通阅读和提问草稿不冻结全页。选择文字时保护受影响块，主动历史查看固定版本，个人试算保留原公式；新内容局部更新，不抢焦点或丢失未提交输入。
- 输入断开时保留最后状态并显示缺口；不把旧画面冒充实时。

## 6. 身份与事实

身份层次：`verified`（有明确映射依据）、`clustered`（声音分组，无实名）、`unknown`。平台账号也可能为共享设备，不能自动证明每句出自某一真人。身份映射修正须传播到依赖产物。

身份不足时允许继续按话题记录观点、理由与分歧。不能把无姓名的不同主张合并成共识；不能把“发言人A”包装成可靠实名。姓名准确率和可归属覆盖率须分开测试，无既定90%／99%效果承诺。

原话、模型解释、假设、试算与决定是不同内容来源。责任人、工期和任务由Agent补充时标为建议。会议决定必须有明确确认范围和依据；一个个人采纳按钮不代表所有参会者同意。

## 7. 首个完整版本的范围

本轮用户追加：macOS 和 Windows 同时为目标平台，分别验收；跨平台架构与构建不能代替真机验证。

必须覆盖：会议事件、线上与线下各一条真实验证的输入路径、持续理解、低打扰入口、Agent生成表达、来源与修订、基础比较／拆解／条件推演、停止与恢复、跟随系统／手动中英语言及中英会议验证。可分阶段交付，完成声明必须指出哪些能力已通过测试。

承载能力涵盖短文本／列表／表格、逻辑图、SVG、结构化数据图表、受控HTML组合表达。每种承载按[实施计划](implementation-plan.md)逐步启用，不能因阶段性只实现一种就宣布全部完成。

可按系统分阶段验证，限制受控少量参会者、单场活动采集、有限基础图元和操作；macOS 与 Windows 同为首版目标；不能把普通会议限制为某类预算会议、所有内容都必须由主持人发放或仅固定模板填充；可选协作组件的正式发放单独遵守下述权限边界。

跨机器共享与多人编辑、手机原生应用、公共平台上架、多租户服务、自动跨会记忆、通用任意应用生成仍可后置。PR #3 已将四类本地协作组件纳入本次整合范围，不能继续笼统写成“所有协作均未开始”。独立桌面应用不意味着所有平台或跨设备能力已通过验收。

### 可选协作扩展与转写接入

依据 [PR #3 的设计、实现与本地对齐](pr3-doc-alignment.md)，投票、分工、冲突、决定确认采用固定业务 schema，与 Agent 自主生成的普通表达并存。Agent 准备私有草稿，发起者在独立悬浮窗检查后发放，指定参与者各自回应；组件就绪只提示，不自动抢焦点。已有会议不自动开启协作，个人查看和推演不依赖参与者名册。

当前首阶段使用同机窗口绑定的模拟身份，不由声音、姓名或模型猜测身份和权限。投票结果、分工展示、本人接受、指定范围决定分别记录；新版不能继承旧同意，有保留／未回应／输入缺口不得静默转成共识。真实跨设备投递与认证不在此次首版范围。

GPT Live Transcribe 已随 PR #3 合入主线：暂定文字只供阅读，最终文本才成为来源并进入理解；首包授权、输入缺口门槛与新版回应重算见[修复证据](../tests/results/pr3-fix-validation.md)。后续私有意图通过明确操作转为正式协作预览，见[分支整合](sessions/2026-09-12-branch-integration.md)。源码、包与真实效果分别核对，不以合入主线代表完整验收。

跨设备共享与多人编辑、手机原生应用、公共平台上架、多租户服务、通用任意应用生成均可后置；已纳入范围的本地协作组件继续保留。

**跨会议主题文件夹（本轮用户确认，纳入范围）。** 用户可以把同一主题的多场会议放进一个**自己建立、自己命名**的文件夹，并生成一份跨会议综合纪要。这不是"自动跨会记忆"：**关联由用户显式声明**，系统不自行判断哪些会议相关，也不会把内容从一场会议泄漏到另一场。自动跨会记忆仍然可后置。

综合纪要只回答决策与未决项追踪，并遵守以下边界：

- **决策、未决项、分歧由确定性检查产出**，不新增模型裁判调用。模型只做跨会议的去重、归组与叙述，不得裁定分歧、不得平均、不得声称已达共识。
- **分歧并列保留**，两侧等权重，并标明并列的依据。丢掉一方比报告变短更糟。
- **每条都应可追溯到具体会议及其依据**。发言依据引用原话；已记录的会议级决定也可作为业务确认依据，保留确认范围，不伪造为转写。当前决定引用可返回所属会议，尚无专门的决定详情定位；原话引用按来源与版本打开。
- **生成是手动触发的不可变快照**；成员会议变化后标记过期，由用户决定是否重新生成。
- 会议之间仍是独立事件；跨会议不合并对象、不共享身份映射。

文件夹与报告已随 `55267d6` 基线合入主线；当前支持 1–8 场会议，删除文件夹不删除成员会议。生成期间成员或定义变化会拒绝新结果并保留旧报告。实现及恢复边界见[工作流运行说明](agent-workflow-runtime.md#跨会议集合与报告)，工程依据见 [ADR-006](adr/006-cross-meeting-collections.md)。

## 当前可靠性落实

用户已确认优先改善理解准确、持续跟进和结果可靠：区分提议／条件／承诺，持续保留有效条件并追踪修订影响，结束时核对未处理内容、分歧与未决项。已落地的机制与尚未验证的语义效果见[可靠性规范](agent-reliability.md)。

## 8. 产品完成效果

用户应能快速回答“当前问题、主要选择、关键分歧、刚发生的变化、下一步与未知项”。通过真实理解任务的正确率、答题耗时、来源核查、修改成功率和打扰观察衡量，基线与数值目标待实测校准。生成图表数量和输出字数都不是主要成功指标。

## 会议提醒与入口可见性

用户确认[会议候选提醒](meeting-reminder-spec.md)：球可见时旁侧气泡，隐藏时系统通知；不确定性文案、点击才记录、忽略无动作。隐藏球只改变展示；托盘及快捷键保留，记录和理解继续。提醒入口开始后不自动打开工作页，首页开始仍按原流程。真实检测器尚未接入，此描述不代表自动发现已经可用。
