# 会议启动、设备设置与内容入口

2026-09-12｜核心入口已随`3f6279a`接入，新前端与轻音频设置随`a587a92`实现；本地应用已按`38c70b1`源码更新。程序验证见[Agent基线](../tests/results/live-agent-validation.md)与[前端及包验证](../tests/results/frontend-refresh-validation.md)，真实供应商及设备质量仍待验收。依据：用户实际使用前端后的反馈，以及“先改清楚规范，代码由正在运行的任务统一接入”的范围确认。

本文件覆盖旧规范中的每次开会填写标题／输入源／输出语言、固定英文默认和空会议常驻提问框。产品方向仍为 `meeting-event-generative-v3`，当前视觉采用[style.md](design/style.md)整理的已认可 8 图方向；`collaborative-light-v2`已由前端改造接入，浅色与内容优先原则保留。旧概念图中的输入栏不再是必须复制的布局。

## 1. 用户确认与实施细化

| 用户已明确的要求 | 本规范给出的实施细化，非用户逐项确认或测试结论 |
|---|---|
| 点击 Start meeting 不应每次填写一组配置 | 配置可用时一次点击创建事件并启动采集；首次设置和设备异常走例外路径 |
| 标题由 Agent 根据会议内容起名 | 开始使用日期时间占位；理解产生依据后命名；手工改名后不再自动覆盖 |
| 麦克风应在初始化／设置中匹配和选择 | 保存系统默认或指定设备；设备失效明确恢复，不静默切到别的麦克风 |
| 正常开会不使用 Text input，回放不应混在输入选项中 | 正常入口只面向音频；文字／合成回放只在明确开发测试入口保留 |
| 中文／英文跟随系统，其他语言默认英文，设置可改 | 界面与新会议输出各自支持跟随系统；中文系统映射简体中文，其他系统映射英文 |
| 无内容时不出现 Ask about this meeting；有内容后再考虑入口 | 已在内容后使用“进一步讨论”轻入口，点击才展开；已做本地验证，真实使用质量继续按反馈校准 |
| 前端需要更好的审美和层次 | 通过信息主次、留白、排版、表面层级和控件权重改进，不将装饰数量当作质量 |

## 2. 正常使用路径

**首次使用：** 展示一次简短音频设置，默认选系统麦克风，允许更换；用“麦克风：本地发言”“同时收听电脑声音：线上参会者”解释处理范围。保存设置本身不录音。首次点击开始时完成必要的系统授权，再进入采集。若提供设备测试，只在用户点击测试后短暂采集并释放，不把测试音频送入会议。

**之后每场会议：** 首页只有一个明确的 `Start meeting` 主按钮，旁边用低权重摘要显示将使用的麦克风及是否收听电脑声音，提供更改入口。从首页点击后进入会议工作页；通过会议候选提醒点击开始则只在原入口反馈状态，不自动展开工作页。标题、语言、来源无需重复填写，也无需再点一次 `Start input`。这表示应用正常流程一键开始，不承诺消除操作系统可能要求的授权或选择界面。

**已有活动会议：** 主操作为 `Open meeting`，打开原事件；不会新建第二场，也不会因打开页面恢复被暂停的采集。暂停后通过明确的恢复操作继续；应用重启恢复内容，不自动录音。

**没有可用配置：** 展示对应设置或修复项。麦克风／STT不可用时不能用手工文字模式代替并显示开始成功；模型不可用与采音失败分别说明。原始输入能够接收但暂时不能理解时如实显示，不生成假内容。

## 3. 设备与声音范围

设置中的音频区包含：麦克风选择、是否同时收听电脑声音、实际设备状态。首次默认“系统默认麦克风，电脑声音关闭”是实施默认值，不代表已选择线下作为唯一产品场景；需要收听线上会议时开启电脑声音并记住选择。不能靠猜测某个会议软件正在运行就扩大采集范围。

- “系统默认”跟随系统选择；“指定设备”保存设备标识与用于展示的名称，不能只按名称猜匹配。同名设备、设备标识改变、插拔后重新验证。
- 会中实际采集设备／通道由采集层回报。系统默认设备变化也必须反映真实路由；若需要重新连接，显示切换过程和缺口。
- 已指定的麦克风缺失时显示“原设备不可用，选择麦克风”；不悄悄换到内置麦克风。修复后恢复同一事件。
- 电脑声音开启时，本地麦克风与电脑声音是两个通道，不能将来源名称当作人物姓名。电脑声音不可用时不能声称已收听线上参会者；允许用户明确选择只用麦克风继续。
- 修改全局偏好只影响下次启动；活动会议若需切换，提供明确的“应用到当前会议”，由采集层切换并记录必要缺口。更新配置不等于更新实际采集状态。
- 收听范围与当前状态可见；关闭窗口继续后台，暂停／结束释放对应资源。正常 UI 不出现 `manual`、`replay` 等内部模式名称。

## 4. 一次开始意图如何衔接前后端

前端提交“开始一场会议”的意图；可信桌面协调层解析已保存的偏好、校验可用性、创建事件并启动采集。不能只删掉表单，却仍要求前端用虚构标题和隐藏默认 `manual` 满足旧接口。

建议对外契约如下；名字可依现有结构调整，职责和返回语义必须保留：

```ts
type StartMeetingRequest = {
  requestId: string; // 幂等；同一次点击重试复用
};
type StartMeetingResult = {
  meetingId: string | null;
  state: 'needs_setup' | 'starting' | 'capturing' | 'input_error';
  reason?: string;
};
```

桌面层读取时区、系统语言和设备状态；领域服务解析会议配置并持久化；采集层持有设备权限与音轨；Agent只接收会议内容与输出语言，不能修改设备或启动录音。

| 阶段 | 必须完成的行为 |
|---|---|
| 预检 | 配置缺失先返回 needs_setup；无有效STT时给出配置入口，不先制造可采集的成功状态 |
| 创建 | 服务端生成事件ID、时间与占位名称，快照保存本场输出语言及声音范围；一次意图最多创建一个事件 |
| 启动 | 已创建则可立即打开工作页并显示“正在连接”；仅收到音轨就绪确认后显示“正在收听” |
| 连点／重试 | 前端禁用启动中的按钮；后端仍做幂等和单活动事件校验，不能只依赖按钮禁用 |
| 启动失败 | 释放已打开的部分资源；保留已创建的同一事件和明确错误，修复重试不创建副本 |
| 取消／结束竞争 | 取消设置不建事件、不留音轨；若事件已创建，停止本次启动尝试并保留可恢复的暂停事件；结束使旧采集代次失效，晚到成功不能复活采集 |

会议生命周期与采集状态分开：事件存在不代表设备已就绪，设备已就绪不代表 Agent 已产生内容。复用已有 epoch／lease 和幂等机制，勿另造一套互相冲突的状态机。

### 偏好契约

偏好至少表达 `uiLanguage: system | en | zh-CN`、`defaultOutputLanguage: system | en | zh-CN`、`microphone: system-default | deviceId`、`includeComputerAudio`、`audioSetupCompleted`。这些语义现已接入；源码使用uiLanguage、defaultOutputLanguage与audio对象，实际字段见src/contracts/model.ts。

`audioSetupCompleted`只表示设置完成，不能当作权限永久有效。旧数据迁移保留已保存语言；旧结构没有选择来源标记，不能把保存的英文认定为用户显式选择，也不能盲目覆盖。保守保留并允许在设置中改为跟随系统；新安装默认跟随系统。

## 5. 自动标题

开始时展示本地化的“会议 · 日期时间”，让用户立即识别事件；没有内容或模型失败时一直保留这个真实占位，正常流程不要求手工补标题。

Agent在已有理解流程中，根据足够的会议内容提出简短标题；不直接把第一句原话、最新焦点或产物问题当作会议名称。只因稳定主题形成或主题发生实质改变而更新，避免每次发言都改列表名称。结束整理可更新仍由 Agent 管理的标题。

建议标题带 `origin: placeholder | agent | user`、`revision`、来源引用及依赖版本。校验事件ID、来源版本、目标语言及标题版本；手工改名会锁定用户标题，晚到的自动命名不得覆盖。标题生成失败不阻断采集、理解和表达。此契约已接入Agent输出、服务提交和持久化；程序测试证明手工标题不会被晚到提案覆盖，真实命名质量尚未验证。

## 6. 语言

默认跟随系统，中文系统使用简体中文，其余系统使用英文；设置保留跟随系统／English／简体中文。移除页面角落、顶栏和独立右键快捷项的常驻语言切换，通过 Settings 统一管理。

界面语言控制应用外壳，在设置中选择后立即独立保存和切换，保留其他未保存草稿；默认输出语言在新会议开始时解析并保存到事件。系统或界面语言变化不悄悄重写活动会议和历史产物。当前会议输出语言仅在设置中明确更改；语言修订与旧响应处理沿用原规则。发言和引用始终保留原语言。完整规则见 [语言规范](language-spec.md)。

## 7. 内容与提问的渐进出现

| 状态 | 页面显示 | 提问行为 |
|---|---|---|
| 连接设备 | 清楚的连接状态与必要的恢复操作 | 无输入框，无占位底栏 |
| 正在收听，尚无可用内容 | 简短状态：“正在收听，有值得整理的内容时会在这里呈现” | 无输入框，不催促用户输入 |
| 已接收原话，正在理解／表达 | 表明处理阶段；有积压或失败则如实说明 | 不因收到原话或加载占位就打开提问 |
| 出现有意义的 Agent 内容 | 内容成为主视觉，可以是文字、关系、比较或其他表达 | 出现“进一步讨论”等轻入口；无需等到生成图片 |
| 用户主动展开 | 在内容附近展开紧凑操作区，可带选中对象／产物版本标签 | 输入、比较、推演；关闭后回到内容 |

“进一步讨论”已接入内容附近并完成本地交互验证；用户认可整体方向，未对每一细节作独立验收。产物／对象级版本上下文、发送时冻结的个人基线及草稿生命周期见[当前实现边界](frontend-spec.md#11-当前实现与目标差距)。确定不变的是：空状态没有对话框，有内容也不自动展开对话框，产品不变成聊天记录页面。

提问关联实际上下文（事件、选中对象／产物ID与版本），请求与真实会议发言分开存储。自动更新时保留已展开的面板、焦点与草稿；基础内容修订时提示上下文变化，不悄悄替换用户正在询问的依据。输入法 Enter 行为沿用现有规范；结果成为内容或个人推演，不能当作会议共识。

原话修订仍在来源抽屉；普通会议不提供常驻“添加文字来源”。开发测试的文字注入和 synthetic replay 应隔离到明确测试入口，持续标明来源，禁止无凭证时自动切换为测试答案。

## 8. 视觉落地边界

首页围绕开始／继续会议和最近会议组织；设备摘要是辅助信息，配置问题以一个相关提示处理，不铺满技术说明。开始后围绕会议内容组织，不把同一权重的按钮、计数、版本和日志同时堆在首屏。

- 三层表面：安静的应用背景、稳定不透明的内容面、按需出现的设置／来源浮层。磨砂仅用于外围。
- 三档信息：内容标题与主结论最突出；来源和变化是辅助；revision、tokens、provider host、处理水位等移入诊断／详情，正常用户看到“收听中／整理中／需恢复”等可理解状态。
- 主操作清楚、次操作轻量，结束会议仍可直接找到；按钮使用统一图标、间距与对齐。减少重复边框与卡片包装，通过分组和留白建立层次。
- 使用现有字体、颜色与间距token统一可信外壳和生成内容；不以缩小正文、过淡文字或大面积玻璃换取精致感。具体视觉参数以 [style.md](design/style.md) 为建议起点，交互以 [前端规范](frontend-spec.md) 为准，在实际界面验证。
- 空状态保持有意的留白；首个产物自然接管工作区。不能加入假图、假波形、假参与者来填空，也不能用选定概念图证明实现已具有审美质量。

## 9. 接入点与验收

规范阶段发现的旧入口差距已由Agent实现任务接入：正常入口改为一次启动意图，音频设备与语言偏好持久化，有内容后按需提问，标题具有来源和版本。当前程序结果与未验收范围见 [连续Agent与入口验证](../tests/results/live-agent-validation.md)。本文件下表作为持续维护的职责与验收要求。

| 接入点 | 需要统一完成的改动 |
|---|---|
| `src/ui/main.tsx`、`components.tsx`、`i18n.ts`、`style.css` | 取消每场设置表单、一次启动意图、首次音频设置、渐进提问、视觉层次与双语文案 |
| `src/desktop/main.ts`、采集桥接、`src/integrations/capture.ts` | 系统语言、设备枚举与实际路由、指定设备启动、权限／失败恢复、移除常驻语言快捷项 |
| `src/contracts/model.ts`、`src/domain/commands.ts`、`src/service/session.ts`、`store.ts` | 偏好迁移、启动幂等、事件配置快照、标题来源／版本与提交校验 |
| `src/agent/provider.ts` 及增量上下文 | 有依据的命名、问题上下文引用、个人请求与会议事实分离 |
| 单元与桌面验收 | 合成测试不冒充真实采音；分别验证状态、设备与真实平台效果 |

接入后至少验证：

1. 新安装完成一次音频设置；之后两次新会议均不用填标题、模式或语言，也不用二次 Start input。
2. 连点、超时重试、已有活动事件只产生一个事件；授权拒绝、启动中取消／结束不会留下音轨或复活采集。
3. 重启保留偏好；指定设备拔出时明确修复，恢复仍属原事件；电脑声音失败不冒充双通道正常。
4. 中文／英文／其他系统语言正确解析；手动设置覆盖默认；活动会议输出不随界面设置漂移。
5. 无内容无问答框，有文字或图形内容后才有轻入口，点击才展开；更新不丢草稿、焦点或上下文版本。
6. 自动命名具有内容依据，缺模型保留占位，手工标题不被晚到结果覆盖。
7. 普通入口没有文字输入／合成回放；设置、来源、错误、历史在中英文和800×600／200%缩放下可用。
8. 用实际首页、连接／空状态、首个内容、展开提问和设置截图检查层次；本规范不构成视觉验收通过。

本地前端细化：首次缺少音频配置或设备不可用时使用仅音频设置；普通设置仍可分组查看音频／语言／显示。采集错误横幅的重试指向真实采集恢复，理解错误重试仍指向理解服务。来源纠错关闭后保留草稿，推演上下文标签可以移除。验证见[前端改造](sessions/2026-09-11-frontend-refresh.md)。

## 10. 会议候选提醒入口

用户已确认[双渠道提醒](meeting-reminder-spec.md)：悬浮球可见时旁侧气泡，隐藏时系统通知；统一不确定语气、中英文、点击才记录。该入口复用本文件的预检、幂等、实际音轨就绪及恢复流程，只有工作页自动展开行为不同。真实会议检测器尚未接入。
