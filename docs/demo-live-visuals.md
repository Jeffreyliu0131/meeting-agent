# Demo 可视化与实时编辑

2026-09-12用户明确要求面向评委优先体现生成能力与实时变化。本规范修订此前优先文字／表格、原话核对冻结整份产物的保守取舍。事实、来源、身份与会议确认边界不变。

## 表达选择

- 出现有依据的组成、目标分支、支持／质疑、条件、执行依赖时，主动选择图形；无需用户说“画图”，也不等待讨论得出结论。
- 组成和目标分支适合思路图；执行依赖适合流程；观点与条件适合有语义连线的关系图；已知时间锚点用时间线；实际数量用数据图；真正的多维方案对比用表格。无可表达结构时仍用简短文字，不编造关系或数值。
- 每次有意义变化重新判断表达形式。同一个问题可以从短文／表格切到图；优先一个主图和少量辅助内容。对象、分组、连线和图标含义来自模型，不在生产中写固定会议答案。
- 普通图、时间线及其增量修改与理解同轮返回。自定义SVG／HTML及大型组合才需要独立生成，SVG继续使用受限基础图元。
- diagram增加可选layout：mindmap、flow、argument。思路图按实际关系选中心并展开；流程／论点采用有向分层。10种可选语义图标由宿主受控渲染。连线kind由可信校验对齐原Relation；颜色只辅助，文字标签和来源仍可访问。
- 已有节点尽量保留位置，长标签优先保证空间。新增／修改节点短暂高亮，新增连线短暂绘制；更换布局可以重新排列。窄窗保留可滚动图形及可展开文字关系，不等比缩小文字。

## 实时时序

- Live STT仍以24kHz PCM和约100ms包传输，静音600ms或连续2400ms提交；此前连续上限8000ms。完整段落保留原lease、时间和来源，短尾音／双音轨机制不变。
- 默认MEETING_MIN_BATCH_MS从1500ms降为250ms；显式环境配置继续优先。新发言不会重置既有计时器；正在理解时积累下一批。
- 模型JSON请求启用SSE；只将实际content中的focus／question／summary文字投影为临时草稿，不显示reasoning_content，不提前渲染未校验SVG或提交事实。JSON整包响应仍兼容；断流不当成成功结果，usage继续计账。
- liveDrafts只存在Snapshot，按会议／调用隔离，完成／失败撤销；个人推演草稿不投影到公共会议的实时栏。表达仍经schema、证据和预览校验后替换正文。
- 图形schema的重复片段通过JSON Schema引用复用，减少无意义的请求体占用；完整请求仍受原60000字节预算约束，不通过截断来源腾空间。
- 状态栏显示实际聆听／转写、理解、编排和提交变化。只在实际处理时显示工作指示，无伪造百分比、模拟打字速度或固定答案回放。减少动效偏好关闭过渡和运动。

这些是程序参数和行为，不能把2400ms+250ms当成端到端时延；供应商出字、语义处理与图形预览仍需计入真实测量。

## 阅读与版本

核对原话仅保留对应内容块，其余块和摘要继续跟随；同一purpose因新增对象换了产物ID时仍可局部推进。全量转写入口不冻结全部正文。选中文字仍保护对应块，历史查看和个人试算保留其基线；点击查看更新可主动采用当前内容，来源引用保持精确revision。
