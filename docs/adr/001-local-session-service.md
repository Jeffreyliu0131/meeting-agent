# ADR-001：本机会话服务与桌面外壳

## Status

Proposed｜2026-09-11。产品采用桌面事件形态已获用户认可；Electron、TypeScript、SQLite等为本次工程建议，未实测、未被单独确认为最终技术栈。

## Context

同一个会议需要在工作页收起时持续采集、理解和生成；还需要本机线下音源、可能的系统音频、稳定对象和历史产物。依赖Zoom内嵌页面不能覆盖全部业务。团队规模、演示系统和账号权限未核验。

## Decision

建议以TypeScript实现模块接口，Electron承担窗口与系统适配，React实现可信外壳，独立可信本机服务维护会话与调用模型，SQLite单写持久化。先做个人事件，不强制云部署、多人同步或平台OAuth才能开发核心。

先验证实际演示机的采音与窗口，再锁定依赖版本。模型服务可通过提供商适配器切换；生成代码只在受限表达环境中运行。

## Consequences

正面：会话寿命独立于页面；线上与线下共用状态；减少原型部署依赖；独立仓库可完整交接。

代价：桌面采音因系统而异；原生依赖和打包需验证；本机数据库不自动支持多人协作；云端模型仍需网络与凭证。

中性：未来共享可把同样的会话接口移到认证服务，但不是本轮现成能力。桌面首版不保证手机或所有操作系统。

## Alternatives Considered

- 纯网页：部署简单，但真正桌面悬浮和系统采音受限，不能先假设满足全部场景。
- Zoom App＋云后端：适合平台集成，可作输入／共享扩展；不能成为线下使用前提。
- Tauri／原生桌面：可满足部分要求，但目前没有团队熟悉度或音源验证依据；实际验证若更合适可替换本建议。
