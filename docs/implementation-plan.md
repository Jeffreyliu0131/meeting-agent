# 实施阶段与接续计划

首版协作按[专项实施计划](collaboration-v1-implementation.md)推进，四组件、悬浮窗、M/C/R及本地三人闭环已接入；[验收记录](../tests/results/collaboration-v1-validation.md)逐项区分程序覆盖和未验证项。完整目标设计保留，不以已实现子集替代目标。

本文定义阶段出口和后续工作顺序，不维护实时完成状态。当前进度见[状态页](status.md)，每轮执行与交接见[session 索引](sessions/README.md)，实际验证见[结果索引](../tests/results/README.md)。已有首版实现，接手时不得从空仓库重新执行原设计计划。

## 阶段与出口

阶段是组织工作的方法，不是已核验工时或团队分工；可交叉推进，不能因单项程序测试通过就宣布整阶段产品验收完成。

| 阶段 | 内容 | 出口证据 | 完成声明边界 |
|---|---|---|---|
| P0 环境与风险 | macOS／Windows、音源、模型权限、表达宿主 | 环境、探针、失败记录、构建与 ADR | 包能构建不等于目标系统真机通过 |
| P1 事件与生成核心 | 来源／版本、实际模型、表达、纠正、保存恢复 | 变化输入下真实生成、来源、冲突、恢复 | 测试替身不证明真实语义或泛化 |
| P2 实时输入与入口 | 线上／线下音频、设备设置、一键开始、持续后台 | 多人及线上双方、失败恢复、停止释放 | 本机麦克风探针不等于全场接入 |
| P3 交互与推演 | 比较／拆解、Scenario、确定性工具、可信确认 | 版本／来源／交互／隔离与基线验证 | 被动 HTML 不等于任意生成 JS 已启用 |
| P4 整体交付 | 真实场景、性能／成本、视觉、双端体验 | 对应版本的验收、限制与可复现演示 | 未验证项不能计入通过，发布需当前授权 |

首版已交付部分程序能力，真实模型／音频和双端完整验收仍有缺口。具体已完成范围不能仅由本表推算。

接续顺序为核对活动任务及最终工作树，再验证受影响组合、同步两端包和对应文档；已经关闭的修复不重列为待办，完整目标的其余缺口不随合并自动销项。本计划不重复启动其他任务正在负责的实现或交付。

前端后续以[当前实现与目标差距](frontend-spec.md#11-当前实现与目标差距)和用户最新反馈为准；音频偏好、一键开始、自动标题、系统语言与渐进提问已接入，不再列为未开发。真实验证所需采音、模型调用与外部操作仍须按各任务当前授权执行；此计划不是新授权。

## 文件与责任边界

[源码说明](../src/README.md)提供目录路由。共享 schema／领域规则、服务调度、供应商、输入、渲染与桌面 UI 各保留职责；前端不保存密钥，生成内容不成为业务权威。运行命令以[README](../README.md)和 `package.json` 为准。
