# Agent 工作流升级：业务与实现任务书

状态：2026-09-12本轮工程选定的实现范围，**本轮本地实现与程序验证完成；真实效果待验，见结果记录**。用户授权在研究后复核业务并交给新Session实现；以下具体架构是基于该授权的工程选择，不冒充用户逐条指定，也不表示现行代码已经具备。业务依据优先级为当前用户请求→[产品定义](product-definition.md)／[会议入口](meeting-entry-spec.md)／[表达语言](expression-language.md)→本任务书→[研究报告](research/2026-09-12-agent-architecture-report.md)；实际状态以源码与结果为准。

## 1. 本轮要交付什么

将当前会议Agent升级为**能主动回查会议证据、执行有界个人推演、稳定维护产物并可靠恢复的持续工作流**。采用LangGraph JS编排理解／推演／表达分支，继续由可信本机会话服务掌管业务状态。交付必须贯穿实际UI、服务、持久化和模型协议，不能只有库、demo或测试替身路径。

首要业务主体是一场持续发生的线上或线下会议。用户自然说话，Agent后台理解；用户看内容、纠正、比较或试算时，会议继续。输入未明则保留未知，图形失败则保留可辨状态的上一版，结束时明确未决与缺口。生成图数量、节点数量和框架复杂度不是质量指标。

## 2. 业务—功能—实现对应

| 业务情境 | 必须看到的行为 | 本轮交付及保留 |
|---|---|---|
| 点击开始后自然讨论 | 一次设置后开始；未知身份可理解；新内容持续进入 | 保留现有入口、音源／epoch和语言机制；理解流程迁入有界小图 |
| 讨论跳回此前话题 | 找回相关原话和仍有效条件；不把旧方案重复新建 | 紧凑对象／产物索引、按版本查询、一次主动证据回查、可信ID映射 |
| “审批晚了，那之前安排呢” | 标出哪些结论待核对；有依据才修订 | 保留依赖传播；新增证据读取、影响查询与明确覆盖范围 |
| 用户问“如果换方案会怎样” | 提问绑定实际对象／产物版本，会议继续理解，结果为个人推演 | 独立personal队列／图、比较与确定性计算、基线变化提示 |
| 指代或条件不明 | 先查现有证据，仍不明只问一个具体问题，其余内容继续 | 持久澄清状态、来源与候选、去重、回答／取消／自然消解 |
| Agent更新工作内容 | 同一用途保持稳定ID、局部更新、不丢草稿；失败可修复 | scope安全的ensure、版本绑定、RenderReport与最多一次定向修复 |
| 结束或程序重开 | 内容／来源／历史保留；未完成项真实可见；不自动采音 | 持久任务／提案／幂等提交／失效恢复，closeout衔接新任务状态 |

不退回预算固定模板、主持人发布门槛、单平台目标或纯聊天页面。现有文字、表格、关系图、timeline、chart、SVG／受控HTML组合能力继续可用；新增可信基础组件不限制Agent自主组合。

## 3. 工程选择与吸收边界

1. **采用LangGraph JS局部工作流。** 先建立稳定提交与任务接口，再接个人图和实时小图；生成／验证／修复也形成明确工作流。节点允许普通TypeScript函数，业务库不迁入graph state，不另起Python服务或托管Agent Server。依据[LangGraph官方定位](https://docs.langchain.com/oss/javascript/langgraph/overview)及[研究§5–7](research/2026-09-12-agent-architecture-report.md)。
2. **保留领域服务、SQLite、ModelPort、Electron／React和隔离渲染。** 完整语义模型、来源版本与确认快照为权威；图只产生提案。自动写入补齐与用户命令一致的幂等／读版本规则。
3. **检索先用本会议的结构化索引、现有词项与原话读取。** 有真实可调用的EvidenceRequest分支；不只在prompt要求“查历史”。向量检索、外部知识和跨会记忆不作为本轮依赖。分页／容量变化必须暴露覆盖范围，未读不等于条件撤销。
4. **生成式UI吸收A2UI结构／数据分离。** 本轮在现有Artifact协议实现可信数值／来源绑定及稳定组件身份，不整体迁A2UI／AG-UI。现有自由生成与受控HTML不回退为固定业务卡。依据[当前A2UI协议](https://a2ui.org/specification/v0.9.1-a2ui/)。
5. **语音借鉴连续媒体分工，保留当前采集实现。** 本轮不同时换STT、上Zoom RTMS或加入说话人推断；这些改动会混淆Agent升级的因果评估。保留输入契约与合成音频回归，真实流式音频路线仍按研究实验另验收。

LangGraph使用实施时可核验的稳定版并锁定依赖。研究读到的main RC不直接采用。先检查peer依赖、Zod、ESM/CJS与utility process打包；若发现具体兼容问题，可调整版本或saver实现并记录证据，不能悄悄取消LangGraph或停留在安装成功。

## 4. 必须完成的工作包

### W1 可信提交和可恢复任务

补充持久job、immutable proposal、attempt、唯一成功批次结果、租约fencing和请求哈希。短事务原子保存领域变化、命令结果、处理状态及表达job；模型／网络／预览不在事务内。重启若提案已保存，重发同提案；提交已完成则返回原结果，不再次推理生成另一份同ID命令。

新语义对象／关系使用批内临时ref，由服务分配永久ID后原子解析交叉引用。旧对象必须引用提供的ID；保留旧ID和历史。不能把“服务分配ID”误当作语义去重：新建与修改仍需候选定位依据。

read set由可信装载器产生，覆盖实际依赖的来源、对象、关系及语言／定位配置版本。仅新增无关发言不作废当前结果；相关依赖变动拒绝旧提交。图checkpoint不能替代命令幂等；过期租约的旧worker拒绝提交。

失败批次区分接收、尝试、成功、待核对。达到重试上限后隔离持续失败输入，允许不依赖它的内容继续；依赖缺口的结论保持不完整。若无法可靠判断依赖，保守保留待核对，不能标成功或声称完整覆盖。

### W2 本会议检索与连续记忆

ContextPort返回投影、证据清单、可信读版本与coverage。轻量产物索引独立于完整产物正文，修复当前只在一份产物上生成index的限制。保留active条件、承诺、分歧、未决与待核对目录；按需补原话和依赖。

实现只读工具：按ID／版本读来源、搜索本会议、读取邻近上下文、查询依赖影响；支持hasMore／cursor和总字节限制。模型能在协议中提出明确查询，工具结果进入下一轮判断。中文短词、中英混说、同名不同对象、修订后的旧证据必须有回归。若采用FTS5，不能用trigram静默丢掉双字中文词。

必要记忆过多时按目录＋依赖分页核对；未扫完显示未完成覆盖，不能把全部条件压成无出处的摘要。最小证据闭包仍超限则保留明确错误和可继续的任务状态。

### W3 独立个人推演与LangGraph实时小图

个人请求持有requestId、scope、基线引用及自己的状态／预算／取消信号；不复用会议理解锁。会议处理有保留调用资源；同时满足供应商总并发与现有预算约束。UI能绑定对象ID／revision和产物ID／revision并移除标签；不能只在后端存一个不存在的“已选对象”。

个人图可调用受控证据与计算工具，产生带来源的个人结果；相同请求继续时保留基线，基础变化需提示重基，不能自动改变问题依据。个人回答和采纳不能回写会议事实或升级会议共识。

实时图为context→interpret→validate→可选回查或修复→result。普通成功一次模型调用，默认总计至多2次；一次回查后再判断与修复共享第二次额度。个人图默认总计至多4次模型调用、6次工具执行；表达生成默认至多2次模型调用。网络重试、修复和恢复重试均记账，预算不能重启归零。上限为可配置工程初值；修改须有实验依据。

实时澄清作为持久结果退出图，后续输入继续。个人任务如使用interrupt，每个request独立thread，持久saver需恢复测试。也可用显式持久状态恢复而不引入不必要的checkpoint，但必须实现等价的暂停／恢复和无重复写入，不能只用MemorySaver宣称跨进程恢复。

### W4 低打扰澄清与结束核对

澄清包含问题、候选对象、影响范围、来源、基线和状态。先回查再提问；同一歧义去重；UI提供回答、取消／暂不处理和来源入口。问题自然被后续发言消解时有证据地关闭；候选失效则标过期。不要每轮反复弹窗或把澄清堆成第二个任务管理器。

closeout覆盖已接收未成功输入、失败／等待任务、未决澄清、有效条件和过期结果。允许结束后整理尾部已接受内容；处理完成不等于所有问题解决，ready不表示语义全部正确。重启恢复内容和任务不恢复录音。

### W5 表达增量、计算可信性与修复

统一表达身份及队列合并键，包含meeting、scope、个人分支、稳定purpose与对象角色。显式创建不同用途可共存；同用途更新保持artifact／block身份。scope不同或不同个人请求不得互相取消任务。角色有序的比较不能排序后误合并。

事实性数值优先绑定可信字段／ToolResult，保留单位、来源与计算条件。公式数学关系需可追问的依据；纯模型输出的数字不能自报tool_computed。计算明确区分known／conditional／unknown；量纲不一致、缺参数和除零不能显示一个貌似确定的结果。保留Decimal计算与历史resolved view；不为本轮实现任意公式执行器、日期推断或无依据评分。

RenderReport从实际预览返回blockId、errorCode、尺寸／绑定等可行动信息；一次修复只改表现，不能改已提交事实来消除错误。修复后再验证依赖与预览再提交。失败保持旧版且准确标旧版是否已过期，支持重试。文字选择、焦点、中文输入法、草稿和个人试算值不因后台更新丢失。

### W6 评估、诊断与接续文档

添加可执行的业务状态／检索／恢复／scope测试，实际Electron合成流程覆盖个人推演与澄清。真实provider路径实现并经HTTP契约替身验证；替身不能只在测试分支绕过生产逻辑。语义评估脚本记录必要证据、期望动作、来源版本和人工评分，不将schema通过自动计为语义通过。

新增测试至少覆盖[验收场景](agent-workflow-acceptance.md)；语义语料按研究E2／E3逐步覆盖，关键是明确期望和反例，不能为凑数量复制相同句式。运行本地不调用付费供应商的全量单元、构建、格式、文档检查及Electron回归。报告实际代码版本／hash、测试命令与失败修复，真实模型／音频／Windows真机单独标未测。

## 5. 实施顺序和可调整空间

顺序：W6建立可定位基线→W1→W2＋W3个人切片→W3实时图→W4→W5→W6全量验收和文档同步。同一实现任务持续完成整个范围，不能做完第一个图便交付“全部完成”。阶段后更新session，最终逐项核对W1–W6及验收矩阵。

模块落点参考研究§7。实现者可按实际依赖调整文件边界、表名和内部类型；改变业务行为、降掉必做工作包或扩大外部动作不能自行暗改。发现研究静态判断不成立时，用源码／回归证据纠正任务书与记录，不照搬错误假设。

首个阶段必须先书面回读：五个业务结果、W1–W6、保留项、真实验证边界、最新Git差异及实施顺序，然后立即实施，不等额外确认。这份回读用于捕捉误解，不是新的审批流程。

## 6. 范围和授权

可执行：现有产品核心Agent及必要UI修改、必要依赖安装／锁版本、数据库迁移代码、隔离合成测试、本机构建、回归检查和相关文档同步。不得使用日常真实会议数据库做迁移／破坏性测试；使用临时库和合成数据。新增实现文件可创建，既有文件的删除／移动不由本任务自动授权。

本轮不包含：真实麦克风／系统采音、付费模型／STT调用、外部消息或内容发布、Git commit/push/merge、部署、替换日常安装包、权限变更。无需因为这些后置就停下可执行的实现；准确记录未验收项。也不主动创建更多任务或sub-agent，当前授权只要求一个实现Session。

延后路线：Zoom／LiveKit整套服务、实时STT重写、外部RAG、跨会记忆、多人协作、完整A2UI迁移、工作日历／关键路径、逐句多Agent裁判。它们并非永远不做，本轮核心升级不依赖它们。

## 7. 完成证据

交付一张W1–W6→代码模块→验收ID→结果证据表。分别列出程序已通过、真实模型语义待验、真实音源待验和平台未测。所有失败必须说明修复或剩余限制；“框架已接入”“编译通过”“看起来正常”均不足以结案。

更新技术设计、契约、可靠性规范、表达／前端规范、源码导航、配置说明、测试结果、状态与session。采用决定需注明工程依据与实现状态；研究报告保留当时结论，添加后续入口，不回写成当时已实现。对照[研究完整来源](research/2026-09-12-agent-architecture-report.md#12-源码索引与来源)核验真实使用的API，源码main与稳定包不一致时以安装版本为准。
