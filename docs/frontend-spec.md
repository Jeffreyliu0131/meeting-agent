# 前端页面、桌面入口与视觉实施规范

> 实施更新（2026-09-11）：本轮已开始并完成一版本地实现。本文保留原设计目标；“尚未开发／下一轮”等为设计阶段记录。当前实现差异与平台边界见 [ADR-003](adr/003-cross-platform-first-version.md)，实际通过与未测项目见 [验证记录](../tests/results/validation.md)。
2026-09-11｜UI基线：`editorial-light-v1`。用户已选择本任务三张视觉提案中的第二张，并确认英文默认、中文可选；补充希望参考苹果的克制质感，不抢眼、不妨碍工作。本轮只出文档，实际实现交由另一个工程。

## 1. 设计依据与优先级

实现依据顺序：用户最新确认 → 本规范和[语言规范](language-spec.md) → [设计tokens](design/tokens.json)与[界面文案](design/ui-copy.json) → 选定图片。图片中的示例文字、会议日期、图表结构和光学比例不应硬编码成产品。

保留第二张的浅色、留白、轻导航、排版层次、中央工作内容、按需来源和底部轻量输入。细化为：更克制的标题尺度、适合中英的系统字体、仅外围材质、明确的状态与键盘行为。正文、图形和表格不使用高透明底。

## 2. 页面与组件地图

| 页面／组件 | 默认内容与主操作 | 退出与状态 |
|---|---|---|
| Meeting library | `Start meeting`、当前事件、历史事件；无事件时一个空状态 | 打开事件进入工作页；不自动采集 |
| Start meeting | 标题可选、输入选择、输出语言、简短处理范围说明 | `Start meeting`后才请求必要采集；取消不启动 |
| Meeting workspace | 顶栏、生成工作区域、变化提示、轻量提问；来源抽屉默认关闭 | 关闭窗口回桌面入口；不会停止正在运行的事件 |
| Desktop launcher | 可贴边的小图标、真实运行标记 | 悬停速览、左键打开、右键菜单、拖动定位 |
| Hover preview | 当前事件、一个焦点、最多三条变化；无会议时显示开始入口 | 离开联合区域后收起，点击打开工作页 |
| Context menu | 按事件状态提供操作 | Escape、外部点击或执行操作后关闭 |
| Source drawer | 原话、来源时间／身份状态、翻译入口、纠错入口 | 关闭返回原内容选择与滚动位置 |
| Settings | 界面／默认输出语言、视觉辅助、快捷键 | 修改不重启会议；输出语言规则单独说明 |
| Ended event | 原工作页进入已结束状态，保留产物、决定、未决项和导出 | 重新打开不恢复采音 |

应用导航控制固定，工作内容结构不固定。不能把选定图中的对照表、依赖图和“Latest change”设计成每场会议必须填满的三张卡片。

## 3. 会中工作页的布局契约

### 顶栏

高度建议56 CSS px；从左到右为返回Meetings、事件名称、真实状态，右侧为界面语言入口、事件菜单、Pause／Resume与End meeting。空间不足时次要操作进入菜单，结束会议仍可清楚找到。

系统原生窗口控制保留，应用控件避开系统拖动区域。工作页是正常可移动／缩放窗口，默认不全屏、不强制置顶、不覆盖其他应用；只有轻量入口和临时浮层采用必要的置顶行为。

### 主工作区

参考视口1440×1024，桌面工作内容容器最大宽度1120px，常规外边距32px；低宽度下缩到20px。主标题建议28px，可用空间大时不超过32px；不照抄概念图中过大的标题。

每次优先一个主问题及其生成内容，允许必要的辅助表达。旧话题通过历史／话题导航按需访问，无永久宽侧栏，无自动无限卡片墙。Agent可以生成组合内容，但应遵守同一视觉规范。

### 来源与详情

默认仅显示`View sources`入口，点击具体元素后打开对应来源。宽度足够时显示约320px抽屉；若展开后主内容不足600px，则改为侧面覆盖层，关闭后恢复主视图，不把图缩成小字。弹层不遮蔽不可恢复的当前输入。

### 提问入口

底部提供`Ask about this meeting…`，选中对象时附可移除的上下文标签。用户发问后结果优先成为工作产物，不扩展为占据页面的大段聊天流。Shift+Enter换行，Enter发送时必须避开输入法组合状态。点击Send明确触发同样操作。

提问栏可随窗口布局停靠，不能挡住最后一行内容；预留等高底部空间。模型处理中可继续阅读，不锁住整个页面。

### 尺寸与缩放

至少设计验证1440×1024、1024×768、800×600工作窗口及200%文本缩放。宽度不足时先隐藏次要导航、折叠抽屉、换行控件；表格确需横向滚动时只滚表格区域。不得将整张图等比缩到文字不可读。

## 4. 桌面入口的状态机

展示状态：`collapsed | peek | workspace_open`；菜单状态`closed | open`独立。此前文档中的pinned统一解释为左键打开并持续显示工作页，不要求再点一次图钉才能保持打开，也不代表系统always-on-top。

| 输入／情境 | 必须行为 |
|---|---|
| 启动软件 | 显示入口，不自动录音；恢复事件内容不等于恢复采集 |
| 悬停入口 | 建议250ms后打开速览；不激活其他应用焦点 |
| 鼠标进入速览 | 保持显示；图标与浮层间的间隙也纳入关闭宽限 |
| 离开入口与速览整体区域 | 建议300ms后收起；返回区域取消关闭 |
| 左键点击入口／速览打开操作 | 打开当前事件工作页并保持；无当前事件则打开会议列表和开始入口 |
| 工作页已经打开时再点击 | 聚焦现有窗口，不创建副本、不重新录音 |
| 右键入口 | 打开菜单并关闭／抑制速览，直到菜单退出 |
| 拖动入口 | 位移超过建议6px后作为拖动，不触发点击；结束时贴近屏幕工作区边缘 |
| 关闭工作页 | 隐藏至入口，后台继续；不误发stop命令 |
| End meeting | 执行结束流程并立即显示Ending；音源释放后Ended，已接收内容仍整理则额外标Finishing notes |
| Quit且有进行中的事件 | 在可信确认中说明将结束采集并退出；取消则继续运行 |

时间、尺寸和拖动阈值是初始实施参数，不是已测试效果。鼠标离开隐藏的只是速览，不隐藏已打开的工作页。后台生成完成不自动弹出工作页。

图标建议44×44 DIP，位置记录相对display工作区，拔插显示器后钳制到可见边界。原生窗口命中区贴合实际入口／浮层，透明空白区域不能挡住其他软件。不能声称覆盖所有系统安全界面或独占全屏；目标系统需测试。

## 5. 右键菜单与快捷键

| 状态 | 菜单项 |
|---|---|
| 无活动事件 | Start meeting、Recent meetings |
| capturing | Open meeting、Pause capture、End meeting |
| paused／input_error | Open meeting、Resume capture（来源有效时）／Reconnect input、End meeting |
| draining | Open meeting；显示Ending，禁止重复开始／结束 |
| 通用组 | Language、Keyboard shortcuts、Settings、Quit |

Language设置的是Interface language；菜单／设置中另外明确Meeting output language，不用一个含糊选项同时改变两者。第一版一次只采集一场事件，进行中不再提供可暗中创建第二场的Start meeting。

键盘：Enter／Space打开已聚焦入口；Shift+F10或Context Menu键打开菜单；Escape关闭最上层菜单／速览／来源抽屉并恢复触发点焦点，不停止采集。菜单使用平台原生行为或等价方向键导航。

全局快捷键只优先提供Show/hide meeting，默认未分配，允许用户在Settings录入并测试冲突。开始、暂停与结束不默认注册全局键，避免意外采集／停采。快捷键注册失败必须可见，不吞系统按键。无需持续拦截所有键盘输入。

## 6. 视觉语言与材质

浅色为首版基准：纸白内容面、石墨文字、低饱和蓝强调、细分隔。正文建议15px／1.5行高，辅助文字不小于12px，字体优先系统无衬线并配中文回退；具体token见[JSON](design/tokens.json)。标题不用宣传页式超大字号。概念图的衬线字体是视觉探索，不要求在中英产品中复制。

材质仅用于桌面入口、速览、右键菜单与可选轻顶栏。正文／表格／图形底面保持不透明。可采用轻模糊＋接近不透明的底色＋细边界，避免折射、流光、亮边或随鼠标移动的效果。背景颜色不能改变事实状态的辨识。

苹果材质指南用于参考层级、克制和可读性；不是要求实现原生Liquid Glass或更换为SwiftUI。平台原生材质可用且可靠时使用，否则采用同样层级的实色底。模糊、跨窗口透明和真实桌面背景效果必须在目标桌面实测，不把CSS滤镜存在当作等价能力。[S13](sources.md)

响应Reduce transparency、Reduce motion或对应应用内开关；无法读取系统设置时提供明确开关。减少透明度后改用实色底，保留边界；减少动效后无非必要动画。失去窗口焦点或系统降低效果时不影响内容读取。

普通文字对背景对比度目标≥4.5:1，重要图形边界与控件≥3:1。参考图不提供这些保证，需实际验证。材料背景在亮／暗／复杂桌面上都要检查，不能只测白底。

首版交付浅色；深色模式不作为这一轮已确认必做范围。若后续实现，不直接使用第三张未选定方案替换当前结构。

## 7. 状态、动效与更新

入口状态点：idle中性，capturing绿色，paused琥珀，input_error明确错误标识。点旁的速览／无障碍标签写出状态；颜色不是唯一信息。capturing与Agent processing可同时存在，不能只显示Listening掩盖理解失败。

新内容只在受影响对象上短暂标识，轻变化过渡建议120–180ms；无常驻呼吸、旋转、弹跳。重复状态不重复通知。阅读中重大重排转为`Updates available`，点击后应用新版本；旧内容若已失效必须立即标过期，不能等到用户应用布局才提示。

来源缺失、无数据、开始连接、转写有但理解等待、生成失败、试算基线过期、保存失败均有独立文案。不能为填满空白生成假图、假参与者、假百分比。

## 8. Agent生成内容如何继承外观

宿主向生成器提供`visualProfileId`、目标尺寸、字体尺度、可用颜色／间距／图形语法和locale。Agent可决定内容结构、图形数量与布局，但不能修改顶栏、采集状态、设置或复制一套新的应用外壳。

SVG中使用token映射的颜色与字号；HTML／chart由隔离宿主注入同一视觉配置。代码净化后仍检查是否绕过字号／对比／边界约束。语义需要多系列颜色时提供有限、可区分的序列色，不强制所有数据同色。

生成器不需要逐次复制磨砂CSS。材质由可信宿主提供；产物以可读内容为主。改变产物语言时允许换行重排，但保持业务对象、来源及试算语义不变。
